# Java construct-kinds

_Generated by `nao construct-kinds java` — do not edit by hand._

This file lists every construct-kind the java parser emits for the Educator, with the attribute map each kind carries. Rule authors `applies-to:` one or more of these kinds and `match:` against the attributes below.

## `synchronized_statement`

A `synchronized (expr) { … }` block. The lock expression is unwrapped one layer of parentheses so the inner shape — `this`, an identifier, a field access — is what shows up in attributes.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `lock_expr_kind` | `this`, `identifier`, `field_access`, `method_invocation`, `parenthesized_expression` | Tree-sitter node kind of the lock expression (after peeling one set of parentheses). |
| `lock_expr_text` | source text | Raw source text of the lock expression. Useful for rules that match a specific named lock by convention. |

## `method_declaration`

A method declaration. Carries the method's name so ancestor-context rules can attach (e.g. `equals`/`hashCode` pairing), exposes `is_synchronized` and `is_default` for the modifier-based rules, and emits `throws_types` (only when present) so `checked-exception-over-use` can fire on methods that declare checked exceptions.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Method identifier as written in source. |
| `is_synchronized` | `true`, `false` | `true` when the declaration carries the `synchronized` modifier (implicit lock on `this` for instance methods, on the `Class` for static methods). |
| `is_default` | `true`, `false` | `true` when the declaration carries the `default` modifier — only legal on interface methods. Used by `default-method-in-interface` to discourage growing interfaces via default methods. |
| `throws_types` | source text | Comma-separated list of declared throws-types. Only emitted when the method has a `throws` clause — rules can `match: { throws_types: { present: true } }` for any-throws or check the text for specific exception names. |

## `class_declaration`

A class declaration. Visible as the outermost ancestor when hovering anywhere inside a class body. The `overrides_*` booleans let class-level rules (`equals-without-hashcode`) check the equals/hashCode pairing without re-walking the body themselves, `in_default_package` flags top-level classes whose file has no `package` declaration, and the inheritance attributes (`is_abstract`, `is_final`, `is_sealed`, `extends_type`, `has_abstract_methods`) cover the modifier/superclass shape that rules in the inheritance space need.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Class identifier as written in source. |
| `overrides_equals` | `true`, `false` | `true` when the class declares a method named `equals` (any signature — the heuristic doesn't check for `Object` arg type). |
| `overrides_hashcode` | `true`, `false` | `true` when the class declares a method named `hashCode`. |
| `in_default_package` | `true`, `false` | `true` when this class is declared in a file with no `package …;` line — the JVM's anonymous default package. |
| `is_abstract` | `true`, `false` | `true` when the class is declared `abstract` — it cannot be instantiated directly and may declare abstract methods that subclasses must implement. |
| `is_final` | `true`, `false` | `true` when the class is declared `final` — no subclass may extend it. |
| `is_sealed` | `true`, `false` | `true` when the class is declared `sealed` (Java 17+) — only the types listed in `permits` may extend it. |
| `extends_type` | source text | When the class has an `extends` clause: the source text of the superclass type (e.g. `Employee`, `PaymentMethod`, `AbstractList<String>`). Absent when the class extends `Object` implicitly. |
| `has_abstract_methods` | `true`, `false` | `true` when the class body declares one or more `abstract` methods. Used together with `is_abstract` to catch the `abstract class` with no abstract members anti-pattern. |

## `equality_expression`

A `==` or `!=` comparison (the only `binary_expression` shapes that have a footgun-flavoured reading). Operand types are filled when the operand is a plain identifier referring to a local variable whose declared type the parser can see; cross-file/field-typed operands stay unset.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `op` | `==`, `!=` | The operator — `==` or `!=`. |
| `lhs_type` | identifier text | Declared type of the left operand when it is a local variable. Absent for fields, method results, literals, and operands the parser can't resolve locally. |
| `rhs_type` | identifier text | Declared type of the right operand under the same conditions as `lhs_type`. |

## `method_invocation`

A method call site. The `call_target` attribute combines the receiver text and method name for convenient `match:` use (`Arrays.asList`, `Collections.singletonList`).

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Bare method name (the `name` field of the `method_invocation` node). |
| `receiver` | source text | Raw source text of the receiver (the `object` field) when present. |
| `call_target` | source text | Convenience: `<receiver>.<name>` when both exist, else just `<name>`. Targets like `Arrays.asList` are intended to be matched here. |

## `declared_type`

A type identifier appearing in a declaration position (variable, field, parameter, return type). Used by `raw-types-warning` to flag commonly-generic types (`List`, `Map`, …) used without type arguments. When the source uses a parameterised form, `generic_args` is present; raw uses leave it absent.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Type identifier (e.g. `List`, `String`, `Account`). |
| `generic_args` | source text | Raw source text of the type-argument list (`<String>`, `<K, V>`) when present. Absent for raw uses — that's the signal `raw-types-warning` matches on. |

## `field_declaration`

A field declaration. The visibility/static/final attributes let rules like `public-mutable-static-field` detect leaky global state without scanning bodies.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `visibility` | `public`, `protected`, `private`, `package` | Declared visibility — `public`, `protected`, `private`, or `package` (when no modifier is present). |
| `is_static` | `true`, `false` | `true` when the field is declared `static`. |
| `is_final` | `true`, `false` | `true` when the field is declared `final`. |
| `type_name` | identifier text | Top-level type identifier of the field (the part rules typically inspect — `String`, `Map`, …). |

## `try_statement`

A `try` block. Covers both plain `try` and `try-with-resources` — the `has_resource_spec` attribute distinguishes them so `try-with-resources-opportunity` can teach the pattern without firing on legitimate catch-only blocks.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `has_resource_spec` | `true`, `false` | `true` for `try (Resource r = …) { … }` (try-with-resources), `false` for the plain `try { … }` form. |

## `import_declaration`

A top-of-file `import …;`. Carries booleans for the import-style decisions rule authors care about (wildcard, static) plus the raw imported name for source-specific matches.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `is_wildcard` | `true`, `false` | `true` for `import java.util.*;` and `import static java.lang.Math.*;` — the `.*` form that pulls in every public symbol from the package or type. |
| `is_static` | `true`, `false` | `true` for `import static foo.Bar.baz;` (and the wildcard form `import static foo.Bar.*;`). |
| `imported_name` | source text | The full dotted path being imported, including the trailing `.*` for wildcard imports. |

## `annotation`

A Java annotation written at a declaration site (e.g. `@Override`, `@Resource`, `@SuppressWarnings("unchecked")`). Covers both the no-argument *marker* form (`@Override`) and the form with arguments (`@Resource(name = "foo")`). Rules matching framework-injection annotations like `@Resource` / `@Autowired` / `@Inject` attach here.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Annotation type name as written in source, e.g. `Override`, `Deprecated`, `Resource`. For fully-qualified usages like `@javax.annotation.Resource`, only the unqualified tail is captured. |
| `is_marker` | `true`, `false` | `true` when the annotation has no arguments (`@Override`, `@Deprecated`); `false` when it carries an argument list (`@SuppressWarnings("x")`, `@Resource(name = "y")`). |

## `local_variable_declaration`

A local variable declaration inside a method or block — the `Foo x = …;` line. Exposed so the sidebar can land on the line as a unit when the cursor is anywhere on it, even when no rule or lesson targets it specifically.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `type_name` | identifier text | Top-level type of the declaration as written (`int`, `String`, `Map`, …). For generic types, only the bare head is captured. |
| `is_final` | `true`, `false` | `true` when the declaration carries the `final` modifier. |

## `primitive_type`

A Java primitive type token (`boolean`, `int`, `long`, `byte`, `short`, `float`, `double`, `char`, `void`). Surfaced so the cursor lands here when it's directly on the keyword — gives the reader a clear "you're on a primitive type" anchor even when no rule or lesson attaches.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | `boolean`, `int`, `long`, `byte`, `short`, `float`, `double`, `char`, `void` | The primitive keyword itself — one of `boolean`, `int`, `long`, `byte`, `short`, `float`, `double`, `char`, `void`. |

## `lambda_expression`

A `->` lambda expression — anonymous function that targets a functional interface (`Runnable`, `Function`, `Comparator`, `Predicate`, …). Covers all three parameter forms (`x -> …`, `(a, b) -> …`, `(int a) -> …`) and both body shapes (expression body `x -> x + 1` and block body `x -> { … return x; }`). The `body_kind` attribute is the most useful signal for rules — block-body lambdas often indicate code that has outgrown the lambda form.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `body_kind` | `expression`, `block` | `expression` when the body is a single expression (`x -> x + 1`); `block` when the body is a brace-delimited statement list (`x -> { return x + 1; }`). |
| `parameter_kind` | `identifier`, `inferred`, `typed` | Shape of the parameter list. `identifier` — bare single parameter, no parens (`x -> …`). `inferred` — parenthesised list of parameter names with types inferred (`(a, b) -> …`). `typed` — explicitly typed parameters (`(int a) -> …`, the rarer form). |

## `if_statement`

An `if` / `else if` / `else` chain. tree-sitter-java models `else if` as a nested `if_statement` inside the outer one's `alternative` field; this construct represents *one node* of that chain. The attributes capture whether the then- and else-branches use braces and what shape the else-branch takes, so rules can target the dangling-else footgun or pattern-matching opportunities.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `has_else` | `true`, `false` | `true` when the `if` has any `else` clause (chained `else if` counts). |
| `consequence_is_block` | `true`, `false` | `true` when the then-branch is a brace-delimited block (`if (c) { … }`); `false` for the single-statement form (`if (c) foo();`). The single-statement form is the source of the dangling-else bug class. |
| `else_kind` | `none`, `block`, `if`, `single_statement` | Shape of the else clause. `none` — no else. `block` — `else { … }`. `if` — `else if (…) …` (a chained else-if). `single_statement` — `else foo();`, the unbraced form. |
| `then_kind` | `solitary_if_no_else`, `single_return`, `single_throw`, `other` | Classification of the then-branch body, used by refactor rules. `solitary_if_no_else` — the then-branch is a single nested `if` with no else, so merging the conditions with `&&` is safe. `single_return` / `single_throw` — the then-branch is exactly one return / throw statement (with or without an enclosing block), so any explicit `else` after it is redundant. `other` — anything more complex. |
| `condition_complexity` | `simple`, `compound`, `long` | Bucketed count of short-circuit operators (`&&`, `||`) in the condition expression. `simple` — zero operators, the condition is a single predicate. `compound` — one or two operators, still readable in a glance. `long` — three or more operators, the threshold at which lifting the boolean into a named explaining variable usually clarifies intent. |

## `for_statement`

A `for` loop. Covers both Java forms — classic C-style (`for (init; cond; update) { … }`) and the enhanced for-each (`for (Type item : iterable) { … }`). The `style` attribute distinguishes them so rules can target one form without matching the other. For enhanced loops the element type, element name, and iterable expression are also captured for finer-grained matching.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `style` | `classic`, `enhanced` | `classic` for `for (init; cond; update) { … }`; `enhanced` for `for (Type x : iterable) { … }`. |
| `element_type` | source text | Enhanced-for only: source text of the element type (e.g. `ProductPromotionItemModel`, `String`, `int`). Absent for classic loops. |
| `element_name` | identifier text | Enhanced-for only: name of the loop variable (e.g. `promoItem`). Absent for classic loops. |
| `iterable_text` | source text | Enhanced-for only: source text of the expression being iterated (e.g. `promoItems`, `getItems()`). Absent for classic loops. |

## `switch_statement`

A `switch` — covers both the classic statement form (`switch (x) { case A: … break; }`) and the Java 14+ expression form (`var y = switch (x) { case A -> …; };`). tree-sitter-java emits both under a single `switch_expression` node; the `style` attribute distinguishes them. The `case_style` attribute reports whether the cases use the colon (classic, fall-through) or arrow (modern, no fall-through) form — most rules care about that distinction more than the statement-vs-expression one.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `style` | `statement`, `expression` | `statement` for the side-effecting form (`switch (x) { … }` not in expression position); `expression` for the value-producing form (the result is assigned, returned, or passed). |
| `case_style` | `colon`, `arrow`, `mixed`, `none` | Shape of the case labels in the body. `colon` — every case uses the classic `case X:` (fall-through unless `break`). `arrow` — every case uses `case X -> …` (Java 14+, no fall-through). `mixed` — both styles appear. `none` — the body has no case labels (empty switch). |
| `has_default` | `true`, `false` | `true` when the switch body contains a `default` branch. |

## `while_statement`

A `while (cond) { … }` loop — condition checked before each iteration, so the body may run zero times. The `condition_is_literal_true` attribute lets rules flag the common `while (true)` infinite-loop shape so they can suggest a verified exit path.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `condition_is_literal_true` | `true`, `false` | `true` when the condition is the literal `true` — i.e. the loop is unconditionally infinite and relies on an internal `break`/`return`/`throw` to terminate. |
| `body_is_block` | `true`, `false` | `true` when the body is a brace-delimited block (`while (c) { … }`); `false` for the single-statement form (`while (c) foo();`). The single-statement form is the same dangling-statement footgun as braceless `if`. |

## `do_statement`

A `do { … } while (cond);` loop — the body always runs at least once, then the condition decides whether to repeat. Rare in modern Java because the trailing condition reads poorly; most do-while loops can be expressed as a plain `while` once the first iteration is hoisted.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `condition_is_literal_true` | `true`, `false` | `true` when the trailing condition is the literal `true` — the loop relies on an internal `break`/`return`/`throw` to terminate. |

## `array_creation_expression`

A `new T[…]` array allocation. Covers both the sized form (`new int[5]`) and the literal form (`new int[]{1, 2, 3}`). The `element_type` and `has_initializer` attributes let rules suggest `List.of(…)` / `Map.of(…)` when the allocation is really a fixed-size collection in disguise.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `element_type` | identifier text | Top-level element type as written (`int`, `String`, `Account`). For multidimensional arrays only the innermost type is captured. |
| `has_initializer` | `true`, `false` | `true` when the allocation provides an inline `{ … }` initializer (`new int[]{1, 2, 3}`); `false` for the sized-but-empty form (`new int[5]`). |

## `constructor_declaration`

A `MyClass(…) { … }` constructor. Carries the class name (constructors share their declaring class's identifier), the declared visibility, and convenience booleans for whether the body's first statement delegates to another constructor (`this(…)` or `super(…)`). The `parameter_count` attribute is exposed for rules that flag too-many-args constructors as a builder-pattern smell.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Constructor name as written — the declaring class's identifier. |
| `visibility` | `public`, `protected`, `private`, `package` | Declared visibility — `public`, `protected`, `private`, or `package` (when no modifier is present). |
| `parameter_count` | source text | Number of formal parameters as a decimal string (`0`, `1`, `2`, …). Stringified because the rule predicate vocabulary is string-typed; use `match: { parameter_count: { in: ["5", "6", "7"] } }` to catch wide constructors. |
| `delegates_to` | `this`, `super`, `none` | Shape of the first body statement's delegation. `this` — the body opens with `this(…)`. `super` — opens with `super(…)`. `none` — no constructor-call delegation. |

## `interface_declaration`

An `interface Foo { … }` declaration. Visible as the outermost ancestor when hovering inside an interface body. The `has_default_methods` / `has_static_methods` booleans let rules detect interfaces that have accumulated implementation as a structural smell.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Interface identifier as written in source. |
| `has_default_methods` | `true`, `false` | `true` when the interface declares one or more `default` methods. Heavy default-method use can indicate the interface is being asked to grow like a class. |
| `has_static_methods` | `true`, `false` | `true` when the interface declares one or more `static` methods. |
| `is_sealed` | `true`, `false` | `true` when the interface is declared `sealed` (Java 17+). |

## `instanceof_expression`

An `x instanceof T` runtime type check. Java 16+ added the pattern form `x instanceof T name` which binds the cast in one step — the `is_pattern` attribute distinguishes it from the classic form that still needs a separate cast. `target_type` is the type tested against.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `target_type` | source text | Source text of the type being tested against (e.g. `String`, `EmailNotification`, `List<String>`). |
| `is_pattern` | `true`, `false` | `true` for the Java 16+ pattern form `x instanceof T name` (binds the cast result to `name`); `false` for the classic form `x instanceof T` that requires a separate cast. |

## `throw_statement`

A `throw …;` statement. The `exception_kind` attribute reports the shape of the thrown expression — most throws are `new SomeException(...)`, and rules typically match on the type name there (`exception_type`).

| Attribute | Values | Description |
|-----------|--------|-------------|
| `exception_kind` | `object_creation`, `identifier`, `method_invocation`, `other` | Shape of the thrown expression. `object_creation` — `throw new Foo(...)`, the common case. `identifier` — `throw e;`, re-raising a caught exception. `method_invocation` — `throw factory.build();`, a thrown value from a call. `other` — anything more exotic. |
| `exception_type` | identifier text | When `exception_kind` is `object_creation`: the type name being instantiated (e.g. `IllegalArgumentException`, `RuntimeException`, `Exception`). Absent for the other shapes. |

## `text_block`

A `""" … """` text block (Java 13+ preview, Java 15 standard). tree-sitter-java doesn't have a dedicated node for them — they surface as `string_literal` whose children include `multiline_string_fragment`. We normalise to one construct kind so authors can teach the indentation rules and write rules that nudge multi-line string concatenations toward this form. `line_count` is the rendered line count after the closing-delimiter rule trims leading whitespace.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `line_count` | source text | Number of lines in the literal as written, stringified. Counts newline characters in the literal's source range plus one — so a single-line text block reports `1`, a three-line block reports `3`. |

## `record_declaration`

A `record Point(int x, int y) { … }` declaration (Java 16+). Carries the type name, the component count (the items in the header parens), and `has_instance_field` — `true` when the body declares any non-`static` field on top of the components. Instance fields beyond the components defeat the record's whole point: state goes through the components.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Record identifier as written in source. |
| `component_count` | source text | Number of record components — the parameters in the record header `Foo(a, b, c)`, stringified. |
| `has_instance_field` | `true`, `false` | `true` when the body declares any non-`static` field. The canonical record holds state exclusively through its components; an instance field is a sign the type wants to be a regular class. |

## `method_reference`

A `::` method reference — `String::length`, `customer::getName`, `Account::new`. Equivalent to a lambda that calls one named target; rules typically nudge the lambda form *toward* this when the lambda body is a single call. The `reference_kind` attribute classifies the four shapes (constructor / static-or-unbound / bound / super).

| Attribute | Values | Description |
|-----------|--------|-------------|
| `reference_kind` | `constructor`, `bound`, `static_or_unbound`, `super` | `constructor` when the target is `new` (e.g. `Account::new`). `bound` when the receiver is a value expression (e.g. `customer::getName`). `static_or_unbound` when the receiver is a type (e.g. `String::length`, `Math::abs`) — distinguishing static-method-on-class from instance-method-via-class requires symbol resolution we don't do, so they share this label. |
| `target_text` | source text | Source text after `::` — the method name being referenced, or `new` for constructor references. |

## `enum_declaration`

An `enum Foo { A, B, C; … }` declaration. Carries the type name, the constant count, and `has_mutable_field` — `true` when the enum body declares any non-`final` instance field, the canonical anti-pattern for enums (their whole point is that the named constants are singletons with fixed state).

| Attribute | Values | Description |
|-----------|--------|-------------|
| `name` | identifier text | Enum identifier as written in source. |
| `constant_count` | source text | Number of declared `enum_constant` entries, stringified for `match: { constant_count: "0" }` use. An enum with zero constants is unusual and usually a typo. |
| `has_mutable_field` | `true`, `false` | `true` when the enum body declares any non-`final`, non-`static` field. Enum instances are JVM-singletons whose identity is the constant — mutable instance state breaks the assumption that two references to `Color.RED` describe the same value. |

## `type_parameters`

The `<T>`, `<K, V>`, `<T extends Comparable<T>>` clause on a generic class, interface, or method. Carries each parameter name plus a boolean for whether any of them violates the single-uppercase-letter convention (`T`, `E`, `K`, `V`, `R`, `T1`, `T2`, `K1`/`V1`) — Sun's original generics naming guideline and the one most style guides still follow.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `names` | source text | Comma-joined list of the type-parameter identifiers as written in source (e.g. `T`, `K, V`, `T1, T2, R`). |
| `count` | source text | Number of type parameters, stringified for `match: { count: "1" }` use. |
| `has_non_conventional_name` | `true`, `false` | `true` when any parameter name doesn't fit the conventional shape — a single uppercase letter, or a single uppercase letter followed by a small digit. Lowercase names (`t`), full-word names (`Element`), and long identifiers (`ResultType`) all flip this true. |
| `has_bounds` | `true`, `false` | `true` when any parameter has an `extends` clause (`<T extends Number>`, `<T extends Comparable<T>>`). |

## `ternary_expression`

A `cond ? a : b` expression — the only ternary operator in Java and the only conditional that has a *value* rather than driving control flow. Lives alongside `if` (which is a statement, not an expression) and the modern arrow `switch` expression. The `is_nested` attribute fires when either branch is itself a ternary, which is the readability cliff most style guides flag.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `is_nested` | `true`, `false` | `true` when the `consequence` or `alternative` branch is itself a `ternary_expression` — i.e. the source has chained ternaries like `a ? x : b ? y : z`. Used by `nested-ternary-discouraged` to flag the readability cliff. |

## `catch_clause`

A `catch (… e) { … }` block attached to a `try`. The `is_multi_catch` attribute flags the Java 7+ `catch (A | B e)` shape; `is_empty` flags a catch with an empty body — the canonical "swallowed exception" anti-pattern.

| Attribute | Values | Description |
|-----------|--------|-------------|
| `exception_types` | source text | Source text of the caught exception type(s). For multi-catch this is the full pipe-separated text (`IOException | SQLException`); for single-type catches it's the bare type name (`IOException`). |
| `is_multi_catch` | `true`, `false` | `true` for `catch (A | B e) { … }` (Java 7+ union catch); `false` for the single-type form. |
| `is_empty` | `true`, `false` | `true` when the catch body contains no statements — the canonical exception-swallowing anti-pattern that hides failures from callers and from logs. |
